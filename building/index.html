Building and overseeing tools

Directing an AI build without being a developer.

I do not write the code. AI models do. My part is the part a team still needs a person for: deciding what gets built, writing the rules it may never break, testing that it holds, and keeping it running once nobody is watching.

  • Five products live
  • Published in ChatGPT's app directory
  • Three MCP servers in production
  • Three model vendors used directly
Method

How a build goes.

  1. Write what it must never doBefore features, the hard rules in plain language: a model never computes a date, a name never reaches the model, nothing is sent without a person's sign-off.
  2. One model builds, another attacks itClaude writes the code. A second model reviews it as an adversary, looking for what breaks. I settle the disagreements.
  3. Test on real cases, read the reasonsI grade the system against examples I labeled by hand, and I read why it answered as it did. A good score can hide a wrong reason.
  4. Check the live thingDone means I watched it work end to end where users will meet it. A passing test or a green status is not that.
  5. Give every unattended job an alarmAnything on a schedule is listed in one register with its purpose and its last run, and it has to fail loudly.
  6. Know the billEach answer costs money to produce. I keep a cost map of every paid service, and every public feature has a usage limit.
Integrations

Built to be used from inside the AI assistants people already have.

Most people will not visit one more website. So each product is also a connector: something Claude, ChatGPT or a browser agent can call on its own, with the same sources and the same rules.

A published ChatGPT app

HenryKnows passed OpenAI's review and is listed in ChatGPT's app directory. The reviewed design separates tools that only read from tools that write, labels each one, and keeps no copy of a question or an answer.

Three MCP servers in production

MCP is the open standard that lets an AI assistant use an outside tool. HenryKnows, On the Books and manifest.md each run one, so Claude or ChatGPT can search the sources, get a cited answer, or read and update a person's notes.

One connector, three AI vendors

The same HenryKnows connector is called by Claude, by ChatGPT, and by the agent in Henry Listens, which runs on Meta's models. The sources and citations are identical whichever model is asking.

WebMCP: a browser agent on the page

WebMCP lets a website offer its functions directly to the AI agent in a visitor's browser. My challenge build lets a student's own agent work a case with HenryKnows and a tested rules engine.

Agent-to-agent

HenryKnows also answers over A2A, a protocol that lets one company's AI agent hand a question to another's. It is open, with a daily limit as the only gate.

Model APIs, used directly

Anthropic for streamed, cited answers. OpenAI for fact extraction and long-running report jobs. Meta for live speech with speaker labels and an agent that calls tools in parallel. Each chosen for the job, not by habit.

Evaluation

Two tests I would repeat on any team.

A blind comparison before a switch

Before moving HenryKnows to a new answer engine, I ran old and new on the same fixed set of questions and graded the answers without knowing which was which. The new engine went live only after it won.

Hand labels, and reading the reasons

For a ranking tool, I labeled the examples myself and measured agreement: 53% at first, 76% after a rewrite. A later version also scored 76% and was worse, because it had started penalizing the wrong thing. The number did not show it. The written reasons did.

Operations

Keeping it right after launch.

A reference tool about regulations is wrong the day the regulation changes. So the upkeep is automated, with a person at the point where judgment is needed.

A rule-change watcher

Every four hours it checks the Federal Register and agency pages for anything touching international students, drafts the update with its source, and puts it in front of me for review. When a court order lands, the site can reflect it the same morning.

A security sweep

Each morning an agent checks published security advisories against what my projects depend on and applies the safe fixes, with a log of what it changed.

A workflow watcher

Every six hours another agent checks each automated job, re-runs or repairs what failed, and only brings me in when a decision is needed.

Real visitors, not crawlers

Most traffic to a new site is automated. My analytics separate people from machines before I draw any conclusion from a number.
